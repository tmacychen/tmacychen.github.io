# Robius

Robius 是一个完全开源的、去中心化的、社区驱动的项目,Robius 使用 Rust 进行多平台应用程序开发。

 ## 核心动机

1. 开发者的困境与需求：
  - 现状： 应用开发者希望使用Rust语言进行开发，但由于Rust的应用开发生态系统目前尚不成熟且碎片化，他们感到无从下手。
  - 具体问题：
    - 选择瘫痪： 存在大量零散的、不完整的解决方案，开发者难以做出选择。
    - 集成困难： 不清楚如何将众多不同的项目整合到一个统一的多平台应用开发流程中。
2. 清晰的商业优势：
  - 如果能够提供一个成熟的多平台Rust框架，将为企业带来显著的商业价值。
  - 具体优势：
    - 一致性体验： 为开发者和终端用户提供跨平台的一致体验。
    - 降低成本与加速上市： 避免为不同平台进行重复开发，从而节省成本并加快产品上市速度。
<!--more-->
3. Rust语言的优势与当前不足：
  - Rust的优势（使其成为理想选择）：
    - 内存安全： 提高代码正确性、可靠性，降低调试成本。
    - 高性能： 能够实现响应迅速、流畅无卡顿的用户界面。
    - 无运行时与垃圾回收： 特别适合移动设备，有助于提升能效，延长电池续航。
  - 当前的不足： Rust本身是一门优秀的语言，但在多平台应用开发领域，由于其生态工具的缺失，它尚未成为可行的选择。

综上所述，Robius项目旨在解决Rust在多平台应用开发领域的生态空白，通过提供一个统一的框架，将Rust语言的内在优势转化为实际的应用开发生产力与商业价值。

这些优势与转向 Flutter 的好处大体重叠，开发者广泛更喜欢使用 Rust 而不是 Flutter 所需的语言 Dart，主要因素包括：

- 能够为跨平台的客户提供更一致的体验。
- 由于现代化的技术栈和更好的团队文化/士气，更容易吸引有才华的开发者。
- 消除了跨平台的冗余开发工作，从而：
  - 因生产力提高而节省资金，
  - 缩短上市时间，并且
  - 让开发者能更专注于 UI/UX 质量。

# Robius 项目的目标

- 建立一个 Rust 应用开发社区并推动生态系统发展
- 创建完整应用 + 系统栈的参考设计
- 开发旗舰应用和更简单的演示应用作为概念验证
- （未来）向 Rust 的语言、库和 cargo 团队提供反馈

# Robius的技术目标：

- 高性能：支持高帧率、原生 API较 IPC 进程间通信延迟低
- 快速响应：显示延迟低，硬件图形加速等
- 高效能：电池友好，更节能
- 快速启动应用：排除 Robius 不可控的操作系统组件，目标是2 s 的冷启动，1.5s 的冷启动。
- 快速编译构建：增量编译足够快，以满足交互需求。支持热重载
- 一致性与灵活性：跨平台开发一致性和开发组件的灵活可替代（未来长期计划）

但是 Robius 要达到这些目标需要面临很多挑战，其中最重要的是要满足实际平台，例如Google Play 商店 (Android)、苹果 App Store (iOS, macOS)、微软商店 (Windows)、Flatpak 的 Flathub (Linux) 等平台的要求和标准。因此 Robius 的技术目标需要底层平台的提供响应的支持。


# 简单总结

 Robius 是一个基于 Rust 的开源应用开发框架，试图填补 Rust 生态中对桌面和移动端应用开发的空白。它很像 Flutter，但期望使用 Rust 来完成所有事情，让开发者更专注应用开发，而不是语言之间的交互。

 Robius 试图利用 Rust 语言优势来构造高性能、低延迟、安全稳定的跨平台应用开发框架。Robius 也需要依赖不同平台的 API作为支撑，利用 FFI layer 与不同的底层交互。

 相较于 Dart 语言，Rust 更灵活，零成本抽象，无 VM，更小巧，但同时也更复杂。

 目前 Robius 刚起步，缺少社区支持，三方库匮乏。相比 flutter 起步有 Google 支持，Robius 在前期发展过程中还有较长的路要走。

 目前 Robius 开发框架正在打造旗舰应用，一方面吸引开发者社区的关注与支持，另一方面也为入门开发者提供设计参考与学习示例。

 同时还有一些简单的学习 demo 可参考：

- 简单的待办事项或笔记应用
- 社交媒体新闻源，例如 Twitter, Facebook
- 社交视频分享应用，例如 TikTok, YouTube shorts
- 购物/电子商店应用，例如 Taobao, eBay, Amazon, Etsy
- 基本绘图/素描应用，例如 paint

# 商业发展思路

Robius 是一个跨平台的应用开发框架，主要目标为 Rust 生态提供一个高性能、低延迟、安全稳定的解决方案。因此其诞生之初就有几个明显的标签/符号：Rust、跨平台、行为一致性、高性能、零成本抽象等。

从商业发展角度，可以参考 Qt 的发展思路。Qt 的诞生也是为了解决 C++ 在应用开发过程中的繁琐与复杂问题。Qt 公司的商业化是通过为企业提供商业支持，培训，专业的工具以及技术解决方案和服务。Robius的商业化可以分为以下几个步骤：
1. 完善技术架构与方案，打造旗舰应用，获得社区关注与支持。
2. 从 Rust 社区起步，借助 Rust 的生态力量，从Rust 社区获得需求与反馈，为 Rust 开发者打造最需要的工具。（例如 crate 图形化管理器，依赖分析工具，安全检测工具等）
3. 获得 Rust 社区认可，打造应用社区，推出插件市场/应用市场，尝试从 Rust 社区走向其他开源社区。
4. 通过社区的发展，寻找杀手应用，借助杀手级应用推动商业化解决方案，为其他商业公司提供商业化支持。
5. 在获得一定的社区影响力与商业成绩后，推广培训服务与认证体系，开拓收入渠道。

结合Rust 与 Robius 的特点，可以尝试的几个商业化方向：
1. 目前在嵌入式行业 Rust 有较好的接受度，且嵌入式工程师普遍希望用Rust 替代 C，可以考虑在嵌入式领域尝试。在嵌入式领域目前有slint，但是 slint 是单独的 ui 描述语言，且在嵌入式领域收费，因此 Robius 有较大机会获得社区的关注与使用。
2. 在移动应用开发领域，目前flutter 是广受欢迎的跨平台开发框架。但flutter 在高性能领域/电池敏感领域可能无法胜任，例如大型游戏场景。可以考虑利用 Robius 的优势，在移动应用找到性能与能耗的需求，更好的实现应用落地。例如：图形渲染引擎、实时定位服务、wifi 热点服务等。可能 Rust 在这个领域不是要取代 flutter，更多是让开发者在 flutter 的框架内使用 Rust 来实现高性能与低能耗的服务。
3. 当前是 AI 时代，AI 应用开发呈现爆发式增长，Robius 可以考虑在 AI 应用开发领域寻找机会。例如：AI 应用开发、AI 工具开发等。同时，Robius 的框架设计也可以加入 AI 接口，让 AI 更好的学习 Robius ，更加容易的创建可用的应用程序。
